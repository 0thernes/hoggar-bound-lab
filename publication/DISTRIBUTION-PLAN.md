## Concrete mechanics for the four additional destinations

**ORCID.** Record the work as a preprint/research output with its actual date, not as an accepted journal article. When a DOI later exists, update/group the same work using accurate identifiers. The author is the source of a manual entry. [ORCID manual entry](https://support.orcid.org/hc/en-us/articles/360006896874-Add-works-manually), [work metadata and grouping](https://support.orcid.org/hc/en-us/articles/360006971353-Metadata-in-the-Works-section).

**OpenAIRE.** It aggregates scholarly records; it does not host the manuscript itself. Its sources include repositories and scholarly metadata providers. Keep ORCID and work identifiers consistent, but do not promise a harvesting date: the graph, API, and author-identity features follow different update cycles. OpenAIRE's 4 November 2026 announcement describes expanded claiming as a gradual rollout. The established Search & Link workflow can connect discoverable outputs to ORCID; it is not evidence that an arbitrary new URL has been indexed. [Aggregation model](https://www.openaire.eu/aggregation-and-content-provision-workflows), [ORCID Search & Link](https://www.openaire.eu/openaire-explore-integration-with-the-orcid-search-and-link-wizard), [current rollout](https://www.openaire.eu/recognising-researchers-for-their-work-new-author-identities-in-the-graph).

**Software Heritage.** The documented endpoints are `POST /api/1/origin/save/?visit_type=git&origin_url=<URL-encoded repository URL>` for a request, and `GET /api/1/origin/save/<request_id>/` for its status. Verify the archived release commit after execution succeeds. Repository preservation does not automatically include external release attachments. The official indexed documentation was readable in search results; direct requests encountered bot protection. The later authorized save succeeded and its archived tag/revision/content were verified; see the preservation receipt. [Official API documentation/source](https://docs.softwareheritage.org/_modules/swh/web/save_code_now/api_views.html).

**Internet Archive.** Use the finalized public URL for each capture. A successful landing-page capture does not prove that a linked PDF was saved, so treat the PDF as a second capture and test playback/download. Preserve the timestamped capture URL and the live release's checksum together. This is preservation of an existing public artifact, not journal publication, scholarly indexing, or certification of its mathematics. [Save Page Now scope and limitations](https://help.archive.org/help/save-pages-in-the-wayback-machine/).
